## ❓ 常见问题

**Q: Action 跑了但某板块没新增活动？**
A: 看 Actions 日志。常见原因：① 该分类当天确实没有新活动（正常）；② 源页面结构变了/反爬返回空
（抓取失败会有 WARN 日志，数据靠已有条目兜底，不会清空）；③ 种子源临时 429 限流（脚本会自动重试一次）。

**Q: AI 调用失败（401/欠费/超时）会影响抓数据吗？**
A: **不会**。抓取主链路是纯关键词规则解析，不依赖 AI。AI 只用于 `PENDING_URLS.md`
自然语言条目；失败会自动切备用中转站，再失败也只是该条目记录"处理失败"等待下次重试。

**Q: README 里的过期活动怎么不见了？**
A: 设计如此。`finalize` 会把已结束活动按月归档到 `docs/archive/YYYY-MM.md`（README 统计区
显示"已归档：N 个"），主页面只保留进行中/即将开始的，避免过期信息干扰。

**Q: README 顶部的日历 SVG 不显示？**
A: SVG 是 Action 生成后 commit 进仓库的。确认 Actions 跑成功过一次，且 `docs/calendar.svg`
存在。GitHub 渲染 README 里的 SVG 图片有时有几分钟缓存延迟，强刷即可。

**Q: fork 后 Actions 不跑？**
A: fork 默认禁用 Actions，到 Actions 页点 "I understand my workflows, enable them"，
再按 [Fork指南](Fork指南.md) 配置 Secrets。

**Q: 每天跑会不会消耗很多 AI 额度？**
A: 几乎不消耗。AI 只在 `PENDING_URLS.md` 有自然语言条目时才被调用（日常 0 次），
抓取全靠关键词规则。ChatAnywhere 免费版（每周 50000 点）绰绰有余。

**Q: 在 PENDING_URLS.md 提交的 URL 没抓到内容？**
A: 看处理记录（自动移到「已处理」区）。若写"页面可能需 JS 渲染/登录"，说明该站是
SPA 或反爬，单次抓取拿不到正文——这类站需要写专门解析器或用 Playwright 源
（参考 `blog_collector.collect_heybox_discounts` 的做法，属于开发任务）。

**Q: 想要更炫的可视化页面？**
A: `docs/data/activities.json` + `meta.json` 已经生成好，`docs/index.html` 是现成的
网页版（进度条 + 卡片 + 筛选）。在仓库设置里开启 GitHub Pages（发布 `docs/` 目录）即可访问；
或把 JSON 拿去部署到 Vercel / Cloudflare Pages。

**Q: 想换成私有仓库？**
A: 可以。README 嵌 SVG 的方案不依赖 Pages，私有仓库也能正常跑 Action。
