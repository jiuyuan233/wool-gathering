## 🔧 工作原理

```
┌───────────────────────────────────────────────────────────────┐
│                  GitHub Actions 六时段定时（避开整点）           │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌───────────────────────────────────────────────────────────────┐
│  抓取（各时段分工，全部为关键词规则解析，不依赖 AI）              │
│  · cloud_collector   云厂商活动页（华为云/阿里云/腾讯云）        │
│  · blog_collector    内置博客聚合源 + V2EX + ITAD/itch.io/Reddit│
│  · direct_collector  Epic/Steam/GOG 官方 API                   │
│  · 小黑盒社区/打折帖  （Playwright 渲染 SPA，读 sources.json）   │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌───────────────────────────────────────────────────────────────┐
│  dedup.py  规范化 → 稳定 ID 去重 → 旧值优先合并 → 按日期算状态   │
│            （已归档的 id 直接丢弃，防止过期活动回流）             │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
┌───────────────────────────────────────────────────────────────┐
│  finalize 阶段（每天 18:47）                                    │
│  1. 处理 PENDING_URLS.md（用户提交的 URL 当场抓取 / 自然语言走 AI）│
│  2. 刷新全部活动 status → 过期活动归档 docs/archive/YYYY-MM.md   │
│  3. 生成 docs/data/*.json → calendar.svg → README.md           │
└──────────────────────────┬────────────────────────────────────┘
                           ▼
                 bot 自动 commit & push 回仓库
```

**八大分类**：`ai` / `shopping` / `video-vip` / `netdisk-vip` / `open-source` / `drive` / `games` / `game-discount`。
游戏标题含英文的在末尾附中文翻译（格式 `英文原名 ｜中文译名`）。

### 关键设计

1. **六时段定时**：北京时间 05:17 / 08:23 / 11:41 / 13:37 / 15:53 / 18:47，cron 全部避开整点，
   减轻免费源网站压力。cron 在 UTC 凌晨定义（`17 21 * * *` = 北京 05:17），GitHub 高峰期可能延迟执行。
2. **抓取不走 AI**：博客/云厂商/官方 API 全部用关键词规则解析（稳定、免费、不耗额度）。
   AI（`ai_client.py`，主力 ChatAnywhere `gpt-6.1-sol`，备用 SiliconFlow 自动切换）
   只负责 **PENDING_URLS.md 自然语言条目**的理解，日常调用次数为 0。
3. **源的真实分工**（重要，别被"sources.json 有 62 个源"误导）：
   - **日常轮询源**：`blog_collector.py` 内置 `SOURCES` 字典（异次元/小众软件/V2EX/ITAD/itch.io/Reddit）、
     `cloud_collector.py` 的云厂商页面、`direct_collector.py` 的官方 API、
     `data/sources.json` 里 `type=heybox / heybox-community` 的小黑盒源
   - **登记源**：`sources.json` 里的 `html` 类型源只做登记（用户提交 URL 的去重凭证），
     不参与日常轮询；在 `PENDING_URLS.md` 重新提交同一 URL 可随时手动抓一次
4. **去重合并**：按稳定 ID（标题 + URL 哈希）去重；已有字段优先保留（旧值优先，防止覆盖已确认数据）；
   status 按起止日期每天重算。
5. **过期即归档**：`finalize` 时 `archive_expired()` 把 `status=ended` 或已过截止日的活动按月写入
   `docs/archive/YYYY-MM.md` 并从主数据移除，索引在 `docs/archive/index.json`（按 id 去重，
   重跑幂等）。README 只显示进行中/即将开始的活动。
6. **自动提交**：bot 身份 commit & push 回仓库（`chore(data): {mode} update {日期}`）。
