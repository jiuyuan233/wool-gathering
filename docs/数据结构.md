## 📊 活动数据结构

每条活动 JSON：

```json
{
  "id": "huaweicloud-ai-200-abc123",
  "title": "华为云 AI 200 代金券",
  "category": "ai",
  "source_url": "https://...",
  "claim_url": "https://...",
  "start_date": "2026-10-18",
  "end_date": "2026-10-25",
  "value": "200 元代金券",
  "requirements": ["实名认证", "新用户"],
  "description": "新用户专享，可叠加免费额度",
  "tags": ["代金券", "华为云", "AI"],
  "discovered_at": "2026-10-18T09:00:00+08:00",
  "last_seen": "2026-10-18",
  "status": "active"
}
```

`status` 由起止日期每天自动重算：`active`（进行中）/ `upcoming`（未开始）/ `ended`（已结束）。

### 生命周期

```
新抓取 → normalize（生成 id）→ merge（旧值优先合并）→ status 重算
   → 进行中显示在 README / SVG
   → 结束后 finalize 自动归档：写入 docs/archive/YYYY-MM.md 并从 activities.json 移除
      （归档索引 docs/archive/index.json 按 id 去重，重复归档不会产生重复条目）
```

注意：
- `id` 必须稳定（同活动每次抓取不变），是去重和防回流的依据
- `end_date` 留空 = 长期免费（仅开源工具允许）
- 已归档的 id 再被抓到会直接丢弃（防止源站旧帖让过期活动"复活"）
